Basics

Seven short, focused examples covering the core Gherkin constructs SpecBinder supports — from a single scenario through Rules, Backgrounds, Scenario Outlines, and tags.

📄️ Hello World

The smallest possible SpecBinder example. A single scenario with plain steps — no parameters, no rules, no configuration.

📄️ Step Parameters

How quoted values in Gherkin steps become typed Java method parameters with automatic type inference.

📄️ Implementing Steps

A fully working example — you extend the generated abstract class in a concrete subclass, implement each step method with real assertions, and the tests run green.

📄️ Rules

Gherkin Rule blocks group related scenarios under a business rule. They map to JUnit @Nested test classes.

📄️ Background

Gherkin Background blocks set up shared state for every scenario in their scope. They map to JUnit @BeforeEach methods.

📄️ Scenario Outline

Scenario Outline with an Examples table maps to JUnit's @ParameterizedTest + @CsvSource.

📄️ Tags

Gherkin tags (@smoke, @regression, …) map to JUnit @Tag annotations for selective test execution.

📄️ Convention Discovery

@Gherkin2JUnit with no path argument — the processor finds feature files by convention, looking in the same package as the marker class.
