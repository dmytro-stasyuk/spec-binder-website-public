Getting Started

SpecBinder is a compile-time code generator that transforms Gherkin .feature files into pure JUnit 5 test classes.

Quick Start​

1. Add the dependency​

Add the SpecBinder annotation processor to your Maven project:

<dependencies>
    <dependency>
        <groupId>dev.specbinder</groupId>
        <artifactId>annotations</artifactId>
        <version>0.1.21</version>
        <scope>test</scope>
    </dependency>
</dependencies>

<build>
    <plugins>
        <plugin>
            <groupId>org.apache.maven.plugins</groupId>
            <artifactId>maven-compiler-plugin</artifactId>
            <configuration>
                <annotationProcessorPaths>
                    <path>
                        <groupId>dev.specbinder</groupId>
                        <artifactId>feature-processor</artifactId>
                        <version>0.1.21</version>
                    </path>
                </annotationProcessorPaths>
            </configuration>
        </plugin>
    </plugins>
</build>

2. Write a feature file​

Create src/test/resources/login.feature:

Feature: Login

  Scenario: Successful login
    Given a user with username "alice" and password "secret"
    When the user logs in
    Then the user should see the dashboard

3. Create the marker class​

Create a test class annotated with @Feature2JUnit:

import dev.specbinder.annotations.Feature2JUnit;

@Feature2JUnit("login.feature")
public class LoginTest extends LoginFeature {
}

4. Build and implement steps​

Run mvn compile — SpecBinder generates a LoginFeature base class with stub methods for each step. Implement the steps in your LoginTest class:

@Feature2JUnit("login.feature")
public class LoginTest extends LoginFeature {

    @Override
    protected void givenAUserWithUsernameAndPassword(String username, String password) {
        // your setup code
    }

    @Override
    protected void whenTheUserLogsIn() {
        // your action code
    }

    @Override
    protected void thenTheUserShouldSeeTheDashboard() {
        // your assertion code
    }
}

Run your tests with mvn test — they're standard JUnit 5 tests.
