Everyday

The language support and the workflow you are in all day: writing spec files, keeping the generated tests current, moving between the spec file and the code, running the tests, renaming, reading the step implementations, the editor toolbar, typed doc strings, and inline previews.

📄️ Editing spec files

Highlighting, element folding, formatting, completion, spell checking and the structure view.

📄️ Inspecting generated code

Reviewing the test class SpecBinder generates from a spec file, line by line, in the Test Code pane beside the spec.

📄️ Reviewing step implementations

Reading the step method behind each step, in the Test Code pane, as the caret moves down the spec file.

📄️ Running and debugging

Running a feature, a rule, a scenario or one Examples row from the editor, and debugging in the spec file.

📄️ Viewing execution results

Bringing run results back into the spec file — the status of each scenario in the gutter and on the toolbar.

📄️ Investigating failures

Reading why a scenario failed without leaving the spec file — the failure mark on the step and the error panel beneath it.

📄️ Finding step usages

Finding every spec file step that a step method implements, from the Java code.

📄️ Refactoring steps

Rename and Change Signature on step methods, with the step text in the spec files changed at the same time.

📄️ Typed doc-string parameters

A content type on a doc string, giving its body the editor support of that language and, for images, SVG and HTML, a rendered preview.
