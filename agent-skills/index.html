Agent Skills

A new Gherkin spec might have only a few scenarios. As the suite grows, more work goes into spotting missing cases and repeated rules, keeping each spec focused, and finding every spec that a change affects. Moving a spec can also mean moving the spec's test class and updating the code that refers to that class.

The steps in each spec need work too. SpecBinder generates JUnit tests and step method signatures from Gherkin, but to run those tests against the application, each step method still needs an implementation that uses the right entry points and fixtures. A coding agent can help with that work by following the patterns already in the suite.

The SpecBinder skills give Claude Code and Codex a workflow for the specs and the steps alike: reviewing .specb and .feature files, dividing specs that have grown too broad, implementing the steps, and keeping specs and tests together and organized as the suite grows.

The skills, spec review guidelines, and installation instructions live in a separate repository. SpecBinder skills on GitHub

Skills overview​

SkillWhen to useWhat it does
Review a SpecA spec is new or has changedChecks the spec against the team's review guidelines for missing cases, duplicated rules and other problems, shows each finding beside the spec in IntelliJ IDEA with the reason, and proposes fixes to apply or dismiss
Move Under a New RuleA rule's scenarios show more than one criterionMoves the scenarios you pick under a new rule in the same spec, titled with the criterion they show, narrows the rule they leave, and trims each rule's background to the steps its scenarios rely on
Move Under a New SpecOne Feature covers several subjectsMoves the rules and scenarios you pick under a new Feature in the same file, writes its title and user story, narrows the original's, and links the two with out-of-scope lines
Separate Out SpecsOne file holds several FeaturesMoves Features into separate files, rewrites links between specs to point at the new files, and in a Java project moves the step implementations to the matching test classes
Automate a SpecA spec has steps with no implementationWrites the missing step implementations, reusing the project's fixtures and existing steps, then runs the test class and reports a result for each scenario
Reorganize Spec FoldersSpecs are grouped by layer, such as api/ and ui/, or the folders have become untidyProposes a folder tree grouped by what the system does, then, once the tree is approved, moves specs with their tests, updates packages and references, and runs the affected tests

Setup​

  1. Install the skills package in Claude Code or Codex. The repository lists the supported versions and installation commands. Requirements and setup instructions
  2. For editor integration, install the SpecBinder IntelliJ plugin, enable Settings → Tools → MCP Server in IntelliJ IDEA, and connect your agent to that server. This connection lets the review skill read the editor's copy and publish findings beside the spec.
  3. Ask your agent for the task you want and give it the spec path. For example, ask it to review ShoppingCart.specb for gaps. You can also invoke a skill by name, such as /specbinder:review-spec in Claude Code.

The setup each skill needs:

SkillNeeds
Review a SpecAny project; IntelliJ IDEA with the SpecBinder plugin to show findings in the editor
Move Under a New RuleAny project; a Java project with JUnit 5 to run the tests before and after the move; IntelliJ IDEA with the SpecBinder plugin to review the change before it is made, or to start it from the editor
Move Under a New SpecThe same as Move Under a New Rule; a Java project with JUnit 5 to also move the new Feature's test code into a file of its own
Separate Out SpecsAny project; a Java project with JUnit 5 to move test code as well
Automate a SpecA Java project with JUnit 5 and Maven or Gradle
Reorganize Spec FoldersA Java project with JUnit 5 and Maven or Gradle
